# コードひろば

HTML / CSS / JavaScript のコードだけを投稿できる、「企画」単位の投稿サイトです。
フロントエンドは GitHub Pages、ログインとデータ保存は Supabase（無料枠あり）で動きます。

## 機能

- **登録**：メールアドレス・ユーザー名（新規作成）・パスワード
- **ログイン**：ユーザー名とパスワード
- **パスワード再設定**：登録メールアドレスに再設定リンクを送信
- **企画**：企画主が作成。「他の人も投稿OK」か「企画主のみ」かを後から切り替え可能
- **投稿**：「コード入力」または「ファイル添付」（.html / .css / .js）から選べます。HTMLだけ、またはCSS・JavaScriptをHTMLの中に直接書いた形でもOK（通常は各500KBまで。管理者の承認で最大2MBまで）。プレビュー付き
- **メモ**：投稿ページに、投稿者が改善した点などを書けます（投稿の編集画面で入力）
- **コメント**：企画ページに、ログイン済みの人なら誰でも改善点などを書き込めます（削除は本人か企画主）
- **返信・通知**：コメントに返信できます。自分の企画へのコメントや、自分のコメントへの返信があると、サイト左上のベルに通知が出ます
- **大容量投稿**：通常は500KBまで。超える場合は管理者に「要請」でき、管理者が通知（ベル）から、認める回数を決めて承認すると、その回数だけ最大2MBを投稿できます。管理者自身は、常に最大2MBまで
- **まとめて削除**：企画ページの「🗑 まとめて削除」で、投稿を複数選んで一括削除できます（企画主・管理者はすべての投稿、それ以外の人は自分の投稿だけ）
- **一般公開 / 限定公開**：投稿ごとに「このhtmlを一般公開する」を設定（初期値は公開、投稿後も変更可）。限定公開は企画の一覧には出ますが、プレビュー・コード閲覧・ダウンロードは、作成者・企画主・共同編集者・管理者と、作成者がユーザー名で追加した人だけ。それ以外の人には「公開を要請」ボタンが出て、押すと作成者に通知されます
- **共同編集者**：企画主が、ユーザー名で検索して追加・削除できます。企画の設定変更と、企画への投稿ができます
- **ユーザー管理（管理者のみ）**：登録ユーザーのユーザー名・メールアドレス・認証状況の一覧と、アカウント削除
- **通知**：自分で削除でき、1週間で自動的に削除されます
- **管理者**：管理者アカウントは、すべての企画・投稿・コメントを編集・削除できます（管理者の指定は SQL Editor から。パスワードなどはコードに書きません）。限定公開の投稿もすべて見られ、どの企画にも投稿できます
- **ダウンロード**：未ログインでも誰でも可能（投稿単位：1ファイルHTML / ZIP、企画単位：まるごとZIP）

## ファイル構成

| ファイル | 役割 |

| `config.js` | Supabase の接続情報（あなたの値に書き換える） |
| `schema.sql` | データベースの設定（Supabase で1回だけ実行） |
| `migration_limit_500kb.sql` | 【上限を500KBに上げる前に schema.sql を実行済みの方だけ】更新用 |
| `migration_admin.sql` | 【管理者機能の追加】すでに schema.sql を実行済みの方向け（管理者アカウントの登録も含む） |
| `migration_reply_notify.sql` | 【返信・通知（ベル）の追加】すでに schema.sql を実行済みの方向け |
| `migration_big_upload.sql` | 【大容量投稿（要請・承認制）の追加】すでに schema.sql を実行済みの方向け |
| `migration_visibility_collab_admin.sql` | 【一般公開/限定公開・共同編集者・ユーザー管理・通知の自動削除】すでに schema.sql を実行済みの方向け |
| `migration_memo_comments.sql` | 【メモ・コメント追加前に schema.sql を実行済みの方だけ】追加分の更新用 |

## セットアップ手順

### 1. Supabase プロジェクトを作る
1. https://supabase.com でアカウント作成 → **New project**
2. 作成後、**SQL Editor** を開き、`schema.sql` の中身をすべて貼り付けて **Run**

### 2. config.js を書き換える
**Project Settings → API** にある次の2つを `config.js` に貼り付けます。
- Project URL → `SUPABASE_URL`
- `anon` `public` キー → `SUPABASE_ANON_KEY`

> `service_role` キーは絶対に書かないでください。anon キーは公開されても大丈夫な設計です（データは RLS で保護）。

### 3. GitHub Pages で公開する
1. GitHub で新しいリポジトリを作り、このフォルダのファイルをすべてアップロード（push）
2. リポジトリの **Settings → Pages** → Source を **Deploy from a branch**、Branch を `main` / `(root)` にして Save
3. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

### 4. Supabase に公開URLを教える（重要）
**Authentication → URL Configuration** で次を設定します。
- **Site URL**：`https://<ユーザー名>.github.io/<リポジトリ名>/`
- **Redirect URLs** にも同じURLを追加

これをしないと、確認メール・パスワード再設定メールのリンクが正しく戻ってきません。

### 5. メール送信について
- 初期状態の Supabase のメール送信は**回数制限が厳しい**（1時間に数通程度）ため、実運用では **Authentication → SMTP Settings** で自前のSMTP（Resend、SendGrid など）を設定してください。
- 確認メールを不要にしたい場合は **Authentication → Providers → Email** の「Confirm email」をオフにできます（ただしメールアドレスの正しさは確認されなくなります）。
- パスワード再設定のリンクは、**メールを請求したのと同じブラウザ**で開く必要があります。

## セキュリティ設計と注意点

- **投稿コードの実行は隔離**：プレビューは `sandbox="allow-scripts allow-forms allow-modals"` の iframe（`allow-same-origin` なし）で実行されるため、投稿されたJSからサイトのログイン情報や他ユーザーの操作にアクセスできません。投稿コードをこのサイトのページとして直接ホストすることもしていません。
- **権限はデータベース側（RLS）で強制**：閲覧・ダウンロードは誰でも可。投稿は「企画主、または許可された企画のログイン済みユーザー」だけ。編集は投稿者本人、削除は投稿者本人か企画主だけです。ブラウザ側の画面制御を迂回されても守られます。
- **メールアドレスは公開されません**：ユーザー一覧にはユーザー名だけが入り、メールは Supabase 認証側にのみ保存されます。
- **既知のトレードオフ**：「ユーザー名でログイン」を実現するため、ユーザー名からメールアドレスを引く関数（`email_for_username`）を未ログインでも呼べる設計にしています。そのため、**既知のユーザー名を総当たりすればそのユーザーのメールアドレスを取得できてしまう**弱点があります。公開規模が大きくなる場合は、この関数を Supabase Edge Function に置き換え、ログイン処理をサーバー側で完結させる構成に変更してください。
- **悪意あるコード**：ダウンロードしたコードを実行するのは利用者自身です。サイトには注意書きを表示していますが、通報・管理機能が必要になったら別途追加してください。
- 「コードのみ」の制限は、入力欄をコード専用にすることで実現しています（画像やファイルのアップロードはできません）。

## Vercel で Supabase を中継する（任意）

学校・職場のネットワークなどで `supabase.co` がブロックされる場合、Vercel を中継役にできます。

1. リポジトリのトップに `vercel.json` を置く（`/supabase/...` へのアクセスを Supabase に転送する設定）
2. `config.js` の `SUPABASE_URL` を、Vercel のときだけ `location.origin + "/supabase"` にする
3. 中継に切り替えると、ブラウザの保存するログイン情報の場所が変わるため、一度ログインし直しが必要

## ユーザー名の変更・管理者バッジ（migration_rename_adminbadge.sql）
- 画面右上の自分の名前を押すと、ユーザー名を変更できます。管理者の権限はアカウントに付いているので、名前を変えても引き継がれます。
- 管理者の名前の横には、緑の「管理者」マークが表示されます。
- トップの「自分の企画」ボタンで、自分が企画主の企画だけを表示します。

## 共同編集者の権限・公開対象の管理（migration_collab_perms.sql）
- 共同編集者ごとに、企画主が「限定公開を見る／企画の設定変更／投稿」を個別に許可・禁止できます（企画の設定ページの「共同編集者」欄）。
- 限定公開の投稿のページに「公開対象」欄が出て、作成者・企画主・管理者が、閲覧できる人をあとから追加・削除できます。

## メール認証の催促・凍結・パスワード変更（migration_email_verify.sql）
- メール認証が済んでいない人には、どのページでも上部に催促バナーが出ます（「認証メールを送る」ボタン付き）。
- 登録から7日たっても未認証のアカウントは一時凍結され、認証を完了するまで書き込み・限定公開の閲覧ができません。管理者は対象外です。
- 管理者のユーザー管理ページで、未認証・凍結中の表示と、「認証済みにする」操作ができます。
- パスワード変更（アカウント設定）：今のパスワード → メールに届く認証コード → 新しいパスワード。
- **Supabase の設定**：Authentication → Sign In / Providers → Email の「Confirm email」を OFF にします（ONだと未認証の人がログインできないため）。「Secure password change」は ON にしてください。

## 管理者の認証でログイン可能に・認証の要請（migration_verify_request.sql）
- 管理者が「認証済みにする」を押すと、その人がログインできるようになります。
- メール未認証でログインできないとき、ログイン画面の「管理者に認証を要請する」ボタンで、管理者のベルに通知が届きます（同じ人からは1日1回まで）。通知から、そのまま「認証済みにする」を押せます。

## プロフィール・メッセージ（DM）（SQL: 11_dm.sql）
- 企画主・投稿者・コメントした人の名前を押すと、プロフィール（企画・公開投稿の一覧）が開きます。プロフィールから「メッセージを送る」で、その人とのDMができます。
- 送信は3秒に1回、1通200文字まで（管理者は制限なし）。メッセージは1週間で自動的に削除されます。
- 管理者は、画面の「メッセージ → すべてのメッセージを見る」で、全員のやり取りを確認できます（利用者にもその旨を画面で表示しています）。

## メッセージの編集・削除（SQL: 12_dm_edit.sql）
- 自分が送ったメッセージには「編集」「削除」が付きます。管理者は、すべてのメッセージを編集・削除できます（文字数の制限なし）。
- 送信は Shift+Enter（Enter は改行）。編集中も、Shift+Enter で保存、Esc でキャンセルです。

## ダウンロード許可・プレビューの全画面表示・メールアドレス変更（SQL: 13_dl_email.sql）
- 一般公開の投稿に「ダウンロードを許可する」設定があります。オフでも、作成者・企画主・共同編集者・管理者はダウンロードできます（企画まるごとZIPも同じ）。投稿のあとから、投稿ページのボタンで切り替えられます。
- 投稿ページのプレビューに「⛶ 全画面」ボタンがあります（Esc または「✕ 閉じる」で戻る）。
- メールアドレスの変更は、アカウント設定にあります（今のパスワードで本人確認 → 新しいアドレスの確認メール）。

## 画像・音声ファイル（SQL: 14_assets.sql → 16_project_assets.sql で「企画に登録」する形に変更）
- 画像（png / jpg / gif / webp / svg など）と音声（mp3 / wav / ogg など）は、HTML（投稿）ではなく**企画**に登録します（企画ページの「🖼 画像・音声ファイル」。登録・管理できるのは、管理者・企画主・「投稿」を許可された共同編集者）。
- ファイルごとに「**使うHTML**」を選びます。そのHTMLのプレビューと、ZIPダウンロードには、選んだファイルだけが入ります。HTMLの中では、ファイル名のまま参照できます（`<img src="photo.png">`）。
- ファイルは「**グループ**」に分けて管理できます（例：キャラ画像、効果音）。グループ全体で使うHTMLをまとめて設定することも、ファイルごとに個別に設定することもできます。グループを消しても、中のファイルは消えません（「グループなし」になります）。
- 投稿フォームには、企画のファイルから「この投稿で使うもの」を選ぶ欄があります（投稿者本人も、自分の投稿の分は選べます）。
- 1ファイル500KBまではそのまま登録できます。500KBを超えるファイルは、ファイルごとに管理者の許可が必要です（申請した大きさの5％増しまで）。ファイルの数に上限はありません（容量だけで制限します）。グループは1企画につき20個までです。
- **1企画あたりの容量の上限は、ファイルの合計3MB**（ふだん）です。足りないときは、企画ページの「🖼 画像・音声」欄の「容量を広げる（管理者に要請）」から、5 / 7 / 10MBを要請できます（管理者が通知から許可・却下。管理者は同じ欄から直接変更できます）。最大10MBまで。（SQL: 17 → 18_quota_request.sql。17は18で置き換わります）
- **HTMLの数の上限**：画像・音声のファイルがある企画は**3個まで**、ない企画は**6個まで**です（管理者も同じ）。上限に達した企画には、新しいHTMLを投稿できません。HTMLが4個以上ある企画には、ファイルを登録できません。
- 画像・音声を使うHTMLは、ダウンロードがZIPだけになります。
- 以前の方式（投稿に添付）で登録されていたファイルは、SQLの実行時に自動で企画に移され、元の投稿が使うファイルとして設定されます（同じ名前・同じ中身のファイルは1つにまとまります。同じ名前で中身が違うものは「名前_2.png」のように改名されます）。
- ファイルはデータベース（無料枠 500MB）に保存されます。容量に注意してください。

## 本名の入力と2段階確認（SQL: 15_realname.sql）
- 本名を入力していない人には、どのページでも上部に「本名の入力」バナーが出ます（入力された名前は管理者にしか見えない旨を表示）。
- 登録から3日たっても本名が未入力のアカウントは一時凍結され、入力するまで書き込み・限定公開の閲覧ができません（管理者は対象外）。SQLを実行した時点で、すでにいる人は、そこから3日の猶予があります。
- 本名の確認は2段階です：①本人が入力（または管理者が登録）→ ②管理者が「確認済みにする」（管理者の登録時に「保存して確認済みに」を選べば、①②が同時に成立します）。
- 管理者のユーザー管理ページに「本名」列があります（検索・状態での絞り込み・登録・修正・確認）。ユーザーのプロフィールでも、管理者にだけ本名が表示されます。
- 本人は、確認済みになるまでは何度でも本名を修正できます（修正すると、確認は取り消されて再確認になります）。確認済みになると、本人は変更できません。
- 本名は専用のテーブルに保存され、一般ユーザーはテーブルを直接読めません。他人の本名を取得できるのは管理者用の関数だけです（本人は、自分の入力内容だけ画面で確認できます）。

## お気に入り登録・アクセス数（SQL: 19_favorites_views.sql）
- 企画ページの「☆ お気に入り登録」を押すと登録され、その企画に**新しいバージョン**（新しいHTMLの投稿／HTML・CSS・JSの更新／限定公開から公開への変更）が出たときに、🔔に通知が入ります。登録した人が自分で操作したときは通知されません。限定公開の投稿は、見られる人にだけ通知されます。未読の通知が残っているあいだは、通知を増やさずに最新の内容へ更新します。
- 「お気に入り登録」は、企画名の右の丸いボタンです（登録すると「お気に入り登録済み」になります）。アクセス数は、企画のページを開いた時点で数えます（同じ人は30分以内なら数えません）。
- 企画の一覧には並べ替え（作成順／更新順／アクセス数順／お気に入り数順）があります。更新順は、企画の中のHTMLを最後に追加・編集した順です（HTMLがまだない企画は、作成した日時）。DMの画面は、開いたときに最新のメッセージ（いちばん下）が見えます。一覧と企画ページに「投稿n件」「登録数n件」「アクセス数n回」が表示されます。
- **アクセス数**は、企画の中でHTMLを開いたとき／HTMLをダウンロードしたとき／企画まるごとダウンロードしたときに数えます（企画ページを開いただけでは数えません）。同じ人（ログイン中はユーザー、ログインなしはブラウザごと）は、30分以内に何度来ても1回です。
- ログインしていない人も数えます（ブラウザごとの番号を使うので、ブラウザのデータを消したり別のブラウザを使うと、別の人として数えられます）。

## 画像・音声ファイルをSupabase Storageに保存（SQL: 20_storage_assets.sql）
- 画像・音声の**中身**は、データベース（無料枠0.5GB）ではなく、**Supabase Storage**（無料枠1GB・別枠）の非公開の置き場 `project-assets` に保存します。データベースには、ファイル名・大きさ・保存場所だけが残ります。
- 見られる人は、これまでと同じです（一般公開のHTMLで使うファイルは誰でも／限定公開のHTMLのファイルは、閲覧を許可された人だけ）。置き場が非公開なので、URLを知っていても権限のない人は取り出せません。
- アップロードは「予約 → 保存 → 確定」の3段階です。予約でサーバーが権限・容量・500KB超の許可を確かめ、確定のときに、保存された実際の大きさをもう一度確かめます（申告より大きいファイルは確定できません）。途中で失敗した予約は取り消され、放置されたものも1時間後に片づきます。
- 以前の方式でデータベースに入っているファイルは、そのまま動きます。管理者ページ（ユーザー管理）の「📦 画像・音声ファイルをStorageへ移す」ボタンで、あとからまとめて移せます（見え方は変わりません）。
- 企画・ユーザーを削除すると、その企画のStorageのファイルも消します（まれに消し残しても、容量を少し使うだけです）。
- Storage の通信量（Egress）は、データベースと合わせた月5GBの枠に入ります。

## 画像・音声を「ファイル」として取り出す
- HTMLは、画像・音声を**ファイル名のまま**（例：`<img src="hero.png">`）指定します。ダウンロードするときは、次の3通りがあります。
  - **ZIP**：HTMLと同じ場所に、画像・音声が元のファイル名で入ります（そのまま開けば動きます）。
  - **画像・音声を埋め込んだ1ファイルHTML**：ファイル名をHTMLの中に埋め込み、1つのHTMLだけで動くようにします（画像・音声が多いと、ファイルが大きくなります）。
  - **ファイルとして保存**：投稿ページの「このHTMLで使う画像・音声」の各ファイル、または企画の「🖼 画像・音声」管理欄の「⬇ 保存」で、1つずつ元のファイル名で保存できます。
- 投稿者がダウンロードを許可していない投稿では、これらのダウンロードも出ません。

## フォルダごと、画像・音声をまとめて登録

## 流行順（SQL: 25_trend.sql）
- 企画一覧の並べ替えに「流行順」を追加し、初期選択にしました。
- 企画ごとに、1日ごとのアクセス数を、直近6日分だけ（日本時間の日付で）記憶します。アクセス数の数え方（30分以内の同じ人は数えない）は、これまでどおりです。
- スコア ＝ 直近の2日（今日と昨日）×2 ＋ その前の2日 ×1.5 ＋ さらにその前の2日 ×1 ＋ それより古い分は0。スコアの計算はサーバー側で行い、画面にもAPIにもスコアは出しません（返すのは順位だけです）。
- 同じスコアの企画は、アクセス数（累計）の多い順 → お気に入り数の多い順 → 作成が新しい順。直近のアクセスがない企画は、最後に並びます（その中も、アクセス数 → お気に入り数 → 作成が新しい順）。
- SQLを実行する前のアクセスは、1日ごとには記録されていないので、スコアに入りません（実行した日から溜まります）。

## HTMLの数の上限の引き下げ・読み込みの待ち時間・Internet Cloud（SQL: 26_cloud.sql）
- **HTMLの数の上限**：画像・音声のファイルがない企画は**4個まで**、ある企画は**2個まで**に変更しました（これまでは6個・3個）。すでに上限を超えているHTMLは消えません（新しく投稿できなくなるだけ）。HTMLが3個以上ある企画には、画像・音声を新しく登録できません。
- **HTMLを開いたときの待ち時間**：HTML（投稿）のページを開くと、読み込みを始める前に、ログインしていない人は4秒、ログインしている人は1秒待ちます（待っている間は、中身が空っぽのページになります。説明などは出ません）。待っている間に別のページへ移ったときは、読み込みを始めません。待ち時間は画面側（`app.js` の `OPEN_WAIT_ANON` / `OPEN_WAIT_USER`）の仕組みなので、サイトを通さずに直接APIを呼ばれた場合までは制限できません。
- **続けて開くときは10秒あける**：基本の待ち時間とは別に、前のHTMLの読み込みを始めてから、次のHTMLの読み込みを始めるまでに、最低10秒あけます（`OPEN_GAP_SECS`）。基本の待ち時間が終わったあと、前の読み込み開始から10秒たっていなければ、その分も待ちます（待っている間は、空っぽのページのままです）。読み込みを始める前に別のページへ移った場合は、数えません。前に読み込みを始めた時刻は、ブラウザ（localStorage）に覚えさせます。ブラウザの記録を消す・別のブラウザを使う、といったことまでは防げません（画面側の仕組みです）。同じHTMLを再読み込みしたときも、数えます。
- **未ログインの人は、HTMLがインターネット通信できない**：ログインしていない人に見せるHTMLのプレビューには、通信を禁止する設定（CSP）を、投稿コードより前に入れます。`fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` / `sendBeacon` などの通信、外部の画像・音声・フォント・スクリプト・CSSの読み込み、フォームの送信、外部ページの埋め込みが、できなくなります（画像・音声は、サイトに登録したファイルをHTMLに埋め込む形なので、これまでどおり表示されます）。CSPで止められない WebRTC（`RTCPeerConnection` など）は、使おうとした時点で止めます。通信しようとしたら、サイトの画面に警告ウィンドウ（「インターネット通信はできません。ログインすると使えるようになります」）を出します（1回のページ表示につき1回）。ログインしている人には、制限はありません。
  - 限界：HTMLの中から、`location.href` などで自分自身を外部ページへ移動させる、WebRTC を別の窓（iframe）の中で使う、といったことまでは止められません。通信対戦ゲームを、未ログインの人に使わせにくくするための仕組みで、悪意のある投稿を完全に封じるものではありません。
  - 外部のライブラリ（CDNの `<script>` など）や、外部の画像・フォントを使っているHTMLも、未ログインの人には、読み込まれず、警告が出ます。
- **Internet Cloud（SQL: 26_cloud.sql → 27_cloud_best.sql）**
  - 管理者が許可したHTML（投稿）だけが使えます。
  - 記録できるのは、**1つのHTMLにつき、1人1件の「数字のスコア（自己ベスト）」だけ**です。ベストを更新できたときだけ上書きされ、前より悪い（同じ）ときは前の記録のままです（サーバー側で判定）。「大きいほど良い（得点など）」か「小さいほど良い（タイムなど）」かは、HTMLごとに、投稿ページの「☁ Cloud」の欄で変えられます（はじめは大きいほど良い）。1つのHTMLにつき200人までです（データは1人数十バイトなので、20KBには収まります）。
  - 記録できるのは**ログインした人だけ**で、**ユーザー名**がいっしょに残ります。**ログインしていない人のスコアは記録されません**（コネクタは、サーバーに依頼を送らずに `{ saved: false, reason: "login" }` を返します。サーバー側でも断ります）。読み取り（ランキング）は、そのHTMLを見られる人なら、ログインしていなくてもできます。
  - HTMLからは、**コネクタ（JavaScript）** の `Cloud.me() / Cloud.submit(score) / Cloud.mine() / Cloud.ranking() / Cloud.remove() / Cloud.info()` を使います。**コネクタは、サイトが自動で入れます（29_cloud_auto.sql 以降。後述）**。HTMLに貼る必要はありません。
  - 動く場所は、**コードひろばのプレビューの中だけ**です。プレビューはこれまでどおり隔離された領域（`allow-same-origin` なし）で動き、コネクタは親ページへのメッセージ（postMessage）で読み書きを頼みます。ログイン情報やキーはHTMLに渡りません。ダウンロードして単体で開いたHTMLでは、Cloudは動きません。
  - 許可の流れ：①投稿者・企画の編集者・管理者が、投稿ページ（または編集画面）で「Cloudの利用を申請する」→ ②管理者が許可（管理者ページの申請欄、または投稿ページの「Cloudを許可する」）。管理者は、申請なしで直接許可することもできます。許可を取り消すと使えなくなります（記録は残り、再び許可すると使えます）。
  - 投稿ページの「☁ Cloud」の欄：誰でも、人数とスコアの向きを見られます。管理者・投稿者・企画の編集者は、記録の一覧（ユーザー名つき）の確認、スコアの向きの変更、削除（ユーザーごと・すべて）ができます。
  - コネクタの中身を変えたいときは、`cloud_connector_update.sql` の `$js$ … $js$` の間を書き換えて実行します（`27` を実行し直す必要はありません）。コネクタはサイトのファイルには置かず、許可されたHTMLのプレビューを開いたときだけ、サーバーから受け取ります。

- **Cloudの申請ボタン**：投稿ページの「☁ Cloud」の欄と、投稿の編集・新規投稿の画面（「メモ（任意）」の上）に「☁ Cloudの利用を申請する」を出します（新規投稿では、投稿したあとに押せます）。

## アクセス数の判定をIPアドレスでも行う・画像と音声をブラウザに覚えさせる（SQL: 28_view_ip.sql）
- **アクセス数（同じ人は30分に1回）の判定**
  - **ログインしている人**：これまでどおり、アカウントで判定します。ブラウザの記録（Cookie・localStorage）を消したり、別のブラウザを使ったりしても、数え直されません。
  - **ログインしていない人**：これまではブラウザに覚えさせた目印で判定していたため、記録を消す・別のブラウザ・シークレットウィンドウで、数え直されていました。これを、**アクセス元のIPアドレス**で判定するようにしました（`client_ip()`。Supabase の方式どおり、X-Forwarded-For の先頭を使います。IPv6は、同じ人が使う範囲（/64）をまとめて1つに扱います）。IPアドレスそのものは保存せず、秘密の文字を混ぜた、元に戻せない値（`view_salt` 表）だけを保存します。IPアドレスが取れなかったときは、これまでどおりブラウザの目印で判定します。
  - 注意：学校のように、みんなが同じ出口（同じIPアドレス）からアクセスする環境では、ログインしていない人のアクセスは、同じIPアドレスの人をまとめて1人と数えます（30分に1回）。
  - 注意：サイトを通さずに、Supabase のアドレスへ直接、細工したヘッダーつきのアクセスを送る人までは、防げません（完全に防ぐには、サーバー側の仕組みが別に必要です）。
  - 管理者ページの「🌐 アクセス数の判定（IPアドレス）」で、「サーバーから見えるIPアドレス」を確認できます。ご自分のIPアドレスと一致していれば、正しく取れています。
- **画像・音声のブラウザへの保存（通信量の削減）**：Storage から取り出した画像・音声は、ブラウザの IndexedDB にも覚えさせて、次に開いたときは、取り出し直しません（ファイルの path にはファイルごとの番号が入っていて、同じ path の中身が書き換わることはないため、古くなりません）。覚えさせる量は、合計約50MBまでで、超えたら、使われていない古いものから消します（`ASSET_IDB_MAX`）。path は、見る権限のある人にだけサーバーが教えるので、権限のない人が、覚えさせた中身を取り出すことはできません。IndexedDB が使えない環境では、覚えさせずに、これまでどおり動きます。

## Cloud：自己ベストのブラウザ保存・ランキングの2秒待ち（SQL: 27_cloud_best.sql をもう一度実行）
- **オンライン自己ベストを、ブラウザにも覚えさせる**：Cloud に記録した自分のベストを、ブラウザ（localStorage）にも、ユーザーと投稿ごとに覚えさせます（`kh_best:<ユーザーID>:<投稿ID>`）。`Cloud.mine()` は、覚えていれば、通信せずにすぐ返ります。`Cloud.submit()` の結果（記録できたときも、できなかったときのいまのベストも）、`Cloud.ranking()` で読み込んだ自分の分、でも更新します。`Cloud.remove()` で消えます。覚えた値は、30分たったら、サーバーで確かめ直します（別の端末で更新された・管理者に消された、などに備えて）。ログインしていない人は、覚えません（`mine` は null）。
- **ランキングの読み込みは、呼ばれてから2秒待って始める**：`Cloud.ranking()` は、呼ばれてから2秒たってから、サーバーへの読み込みを始めます。待っている間に続けて呼ばれたものは、まとめて1回にします（`CLOUD_RANKING_WAIT`）。この待ちは、サイト側（`app.js`）で行うので、HTMLに貼ったコネクタを書き換えても、待ち時間は変わりません。記録の送信（`Cloud.submit`）は待たせません。
- コネクタ（`Cloud.mine()` の呼び方）が変わったので、**`27_cloud_best.sql` をもう一度実行**すると、受け取れるコネクタが新しくなります。すでにHTMLに貼ってある古いコネクタも、そのまま動きます（`mine` が、少し遅くなるだけです）。


## Cloudコネクタの自動挿入・コネクタ配布の廃止（SQL: 29_cloud_auto.sql）
- **Cloudが許可された投稿は、プレビューに、サイトが Cloud コネクタを自動で入れます**。投稿者がコネクタをHTMLに貼る必要はありません。許可されていない投稿には入りません（`Cloud` は未定義のまま）。
- **ダウンロードされるHTML・ZIPには、コネクタは入りません**（ダウンロードは、投稿に書かれたコードそのままです）。そのため、ダウンロード版では `Cloud` がなくなります。HTML側で、`typeof Cloud === "undefined"` を調べて、Cloudなしでも動くようにしておいてください（使い方の例は、投稿ページの「☁ Cloud」の欄の「Cloudの使い方」にあります）。
- 入れる場所は、文書の先頭（`<!DOCTYPE>` の直後）です。未ログインのときは、通信の禁止（`NET_GUARD`）が先、そのあとにコネクタです。コネクタは `cloud_connector_for_post(post)` で取得します（Cloudが許可されていて、その投稿を見られる人にだけ返ります。ログインしていない人にも返ります）。
- すでにコネクタをHTMLに貼ってある投稿も、そのまま動きます（二重に入りますが、あとから入る方が使われ、記録が二重に送られることはありません）。
- **削除したもの**：アカウント設定の「☁ Cloudコネクタ」、管理者ページの「コネクタを受け取れるユーザー」、`cloud_users` 表、関数 `get_cloud_connector` / `cloud_connector_ok` / `admin_set_cloud_user`。「Cloudの利用を申請する」は、コネクタの許可がなくても、投稿者・企画の編集者・管理者ならできます。
- 管理者がCloudを許可した直後は、開いているページのプレビューには反映されません。ページを開き直してください。

## 管理者がアクセス数を増減できる（SQL: 30_view_adjust.sql）
- 不正にアクセス数を増やす人への対策です。**管理者だけ**が、企画ページの「📈 アクセス数の調整（管理者）」（はじめは閉じています）から、その企画のアクセス数を変えられます。
- 変え方は2つです。「増やす・減らす」（`-50` で50減る、`100` で100増える）と、「この数にする」。0未満にはなりません（上限は20億）。
- **変更の前に、警告が出ます**（企画名・変更前後の数・流行順に反映するか・理由・記録に残ること）。変更の幅が1000以上のときは、もう一度確認が出ます。キャンセルすると何も変わりません。
- **理由の入力は必須**です（200文字まで）。
- **変更は、すべて記録に残ります**（だれが・いつ・どの企画を・何回から何回に・流行順にも反映したか・理由）。記録は管理者だけが読め（企画ページの調整欄に、その企画の分が新しい順に10件出ます）、一般ユーザーは読めません。企画を削除しても、記録は残ります。
- **流行順にも反映できます**（はじめからON）。流行順は、直近6日分の「1日ごとのアクセス数」で決まるので、数だけ減らしても水増しが流行順に残るためです。増やすときは今日（日本時間）に足し、減らすときは今日から古い日へさかのぼって、引ける分だけ引きます。OFFにすると、表示される数だけが変わります。
- 管理者かどうかは、サーバー側（`is_admin()`）で確認します。画面を書き換えても、管理者以外は変更できません（`admin_adjust_project_views` / `admin_view_adjustments`）。
- 注意：この調整は「表示されるアクセス数」を直すものです。水増し自体は、28番（IPでの判定）で減らせますが、学校のように同じIPを多くの人が使う場所では、完全には防げません。

## 管理者による、企画への警告・アクセス数カウント停止・ランキング除外（SQL: 31_project_moderation.sql）
- 企画ページの「📈 アクセス数の調整・ランキング設定（管理者）」に、3つのスイッチがあります。**3つは、それぞれ独立**に入り切りできます（管理者だけ。企画主も変更できません）。変更の前に確認の警告が出ます。
  1. **警告を表示する**：その企画を開いた画面の**上部**に、「Your access count has been blocked due to suspicious activity that artificially inflates it. No longer can this project stay in the rankings for much longer.」を表示します。**みんなに見えます**（未ログインの人にも）。文面は `app.js` の `ADMIN_WARNING_TEXT` です。
  2. **アクセス数のカウントを停止する**：その企画へのアクセスを、数えません（アクセス数にも、流行順の1日ごとの記録にも入りません。`record_project_view` がサーバー側で止めます）。管理者の手動の調整（30番）は、停止中でもできます。
  3. **ランキングから除外する**：「**流行順・アクセス数順・お気に入り数順**」で順位をつけず、**一覧の最後**に回します（流行順の順位も、サーバーの `project_trend_ranks` が出しません）。「作成順・更新順」には影響しません。**カウント停止とは無関係に、単独で使えます**（カウントしたまま除外／カウント停止だけで除外しない、どちらもできます）。
- 管理者の一覧には、除外中の企画に「ランキング除外中」と出ます（他の人には出ません）。
- これらの列（`admin_warning` / `views_blocked` / `rank_excluded`）は、企画主・ログインユーザーが書き換えられません。変更は、管理者用の関数（`admin_set_project_moderation`）だけです。
- 設定を変えたあと、アクセス数・順位は、一覧を開き直すと反映されます。
- メモ：「更新順」は、いま、企画に更新日時がないため、作成順と同じ並びになっています（この変更とは関係なく、以前からです）。

## JSONのアップロード・1ファイルの上限を企画の容量まで（SQL: 32_asset_json_size.sql）
- **JSON（.json）も、画像・音声と同じように登録できます**。HTMLからは、ほかの画像・音声と同じく、ファイル名のままで読めます（例：`fetch("data.json").then(r => r.json())`、`XMLHttpRequest` でも可）。プレビューでは、ファイル名の部分がデータに置き換えられるので、**ログインしていない人のプレビューでも読めます**（インターネットへの通信は、これまでどおり禁止です）。
  - そのため、未ログインのプレビューの通信の制限を `connect-src 'none'` から `connect-src data:` に変えました（`data:` は、HTMLの中に入ったデータの読み込みだけで、インターネットには出ません）。
  - ファイルの一覧では、JSONは「📄 JSON」と表示されます。「ファイルとして保存」で、元の名前のまま保存できます。
- **1ファイルの大きさの上限が、「その企画の容量」までになりました**（これまでは固定で3MB）。企画の容量が 3MB なら1ファイル3MBまで、5MB なら5MBまで、7MB なら7MBまで、10MB なら10MBまでです。
  - 企画の容量を広げる方法は、これまでどおりです（企画ページの「🖼 画像・音声」→「容量を広げる」で要請 → 管理者が 3 / 5 / 7 / 10MB から許可）。
  - **500KBを超えるファイルに、ファイルごとの管理者の許可が必要なのは、これまでどおり**です（管理者自身は、許可なしで登録できます）。許可された大きさ（申請の5％増しまで）を超えるファイルは、登録できません。
  - 「管理者に許可を要請」には、企画の番号が渡されます。**その企画の容量より大きいファイルは、要請の段階で断られます**（許可されたのに登録できない、ということが起きません）。
  - 容量の合計のチェック（1企画の、ファイルの合計）は、これまでどおりです。容量いっぱいまで使っている企画には、1バイトも足せません。
  - サーバー側（登録・確定の関数、Storage の置き場の上限10MB、表の制約）でも同じ上限を確かめます。画面を書き換えても、上限は超えられません。

## 複数のJavaScriptファイルの投稿（SQLの変更はありません）
- 投稿に、**JavaScriptのファイルを複数（20個まで）**付けられます。「ファイル添付」で、.html・.css と一緒に、.js を何個でも選べます（HTML・CSSは、これまでどおり1つずつ）。
- 選んだJavaScriptは、一覧に「a.js（JavaScript 1/3）」のように出て、**↑↓で並べ替え**・「外す」ができます。**上から順に動きます**。
- 保存の形：データベースは、これまでと同じ「JavaScript欄」1つのままです。その中に、ファイルごとの**区切り行**（例：`/* ===== file: game.js ===== */`）を入れて、別々のファイルとして扱います。そのため、公開範囲・大きさの上限（JavaScriptの合計、通常500KB）・ダウンロードの許可などは、これまでと同じです。サーバーでは、個数は確かめていません（20個までは、画面で確かめます）。
  - 「コード入力」でも、同じ区切り行を書けば、複数のJavaScriptにできます。区切りより前の部分は `script.js` になります。区切り行がない投稿は、これまでどおり、1つの `script.js` です。
  - ファイル名に使えるのは、英数字・`_`・`-`・`.`・空白（60文字まで）で、最後が `.js` です。使えない名前・重なる名前は、`script.js`・`script2.js` のようになります。
- **動き方**
  - プレビュー・「HTML（1ファイル）」：JavaScriptごとに別々の `<script>` として動きます（1つの文章につなげないので、1つのファイルにエラーがあっても、ほかは動きます）。HTMLの中に `<script src="game.js">` があれば、そのファイルの中身が**その位置**で動き（`defer` や `type="module"` 付きは、ページを読み終えたあとに動くよう、最後に入れます）、ほかのファイルは、HTMLの最後に、順に入ります。
  - ZIP：JavaScriptごとに、別のファイル（`game.js` など）として入ります。HTMLの `<script src>` は、そのままです（なければ、`index.html` の最後に、順に `<script src>` を足します）。
- 投稿ページの「JavaScript」のタブには、全体（区切り行つき）が出て、複数のときは「JavaScript（3個）」と出ます。

## 安全性の改善と、DMのブロック・受信拒否（SQL: 36_security_dm.sql）
- **ユーザー名からメールアドレスを取り出せなくしました**：これまでは、ログイン前の誰でも、ユーザー名を指定してメールアドレスを取得できました（`email_for_username`）。この関数をなくして、「ユーザー名とパスワードが合っているときだけ」ログインに必要なメールアドレスを返す関数（`login_email`）にしました。パスワードを何度も試す攻撃を防ぐため、同じユーザー名で、15分間に8回まちがえると、いったん受け付けなくなります（その間は、メールアドレスを入力すれば、ログインできます）。ログイン画面の入力欄は、「ユーザー名（またはメールアドレス）」になりました。
- **他人名義の「管理者に認証を要請する」を、できなくしました**：要請には、そのユーザー本人のパスワードが必要です（ログイン時にパスワードを入力するため、利用者の操作は、これまでと変わりません）。
- **Cloudの管理の権限に、「Cloudの管理」を追加しました**：これまでは、企画の共同編集者として登録されていれば、Cloudの記録の削除・向きの変更・利用の申請ができました。これからは、共同編集者のうち、企画主（管理者）が、人ごとに「Cloudの管理」をオンにした人だけができます（企画主・管理者・その投稿の作成者は、これまでどおりできます）。**既存の共同編集者は、すべてオフになります。** 必要な人だけ、企画の編集画面の「共同編集者」で、オンにしてください。
- **`Cloud.remove()` は、利用者の確認が必要になりました**：投稿のプログラムが呼ぶと、画面に確認のメッセージが出ます。「キャンセル」されると、記録は消えず、30秒間は、確認も出さずに断ります。
- **メッセージ（DM）のブロック・受信拒否**：メッセージの画面の「🚫 ブロック」で、お互いにメッセージを送れなくなります（ブロックされた側には、「送れません」とだけ出て、ブロックされたことは分かりません）。アカウント設定の「✉ メッセージ（DM）の設定」で、「メッセージを受け取らない」をオンにすると、だれからも受け取りません（あなたからは送れます）。ブロックしている人の一覧と、解除も、同じ場所にあります。
- **未ログインでは使えない関数は、呼べないようにしました**：「ログインが必要」と判定している関数・管理者の関数（`admin_〜`、`decide_〜`）などから、未ログインの実行権限を外しました（動きは変わりません）。
- 先に SQL（36）を実行してから、`app.js` を上げてください（先に上げると、ログインできなくなります）。
